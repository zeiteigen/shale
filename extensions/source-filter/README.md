# Source Filter

Source Filter removes clear noise with deterministic rules and sends only suspicious sources to the LLM. It filters for noise, not personal relevance. Spam and persistent boilerplate can be archived and blocked from reingestion; temporary errors, login pages, and CAPTCHA pages are archived without a block. Bookmarks, notes, documents, explicit manual edits, and manually restored sources are protected. Existing historical evidence and shared graph entities survive removal.

The extension evaluates retained summaries, observed excerpts, coverage, and capture quality; it does not fetch originals or import connector internals. Missing excerpts and short content do not establish noise. Ordinary search, browsing, video metadata, useful newsletters, receipts, code, attachments, and non-English content are retained. Only completely retained failure shells can be removed algorithmically. Excessive boilerplate, repetition, link dominance, or multiple promotional/scam cues trigger review. So does a 64-bit SimHash near-duplicate signal: at least `nearDuplicateMinCopies` other live sources from the same origin and sender, or page host, within `nearDuplicateDistance` bits. Fingerprints are kept in `source_filter_simhash` and looked up through 16-bit bands. The signal never removes a source by itself. Model removal requires confidence of at least 0.90 and exact observed quotations; mixed, inconclusive, or truncated reviews remain live.

Cached decisions and reasons are stored privately in `source_filter_decisions`. Real runs apply cached decisions; dry runs save proposals and log their source IDs, categories, and reasons without removing or blocking sources. Runs use a persistent lease and bounded source/model work. Model requests use the remaining run deadline; waiting for the shared model scheduler may extend elapsed time. Failed reviews are retried after one hour and six hours; after three failures they stop retrying until their content or filtering policy changes. Content, capture quality, and classification settings invalidate decisions; changing execution budgets does not. Settings are read from disk and rechecked before removal.

Run the scheduled job with `cron run source-filter-cron`. For a preview, run `bun extensions/source-filter/index.ts --dry-run`; pass `--source ID` more than once to limit the run to selected IDs. Configure settings with `bun run settings list source-filter` and `bun run settings set source-filter dryRun true`.

The extension uses `sdk.knowledge` for audited removal. Inspect archives using `list_sources` with `status: "removed"` and `inspect_source`; reverse a decision with `restore_source` and `unblockReingestion: true`. A manually restored source remains protected. A useful or protected live capture sharing a browser URL prevents an identity-wide block. This extension adds no endpoint or UI.
